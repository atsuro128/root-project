# セキュリティポリシー

> 詳細な要件定義: `dev-journal/deliverables/docs/10_requirements/requirements.md` §4.2
> RBAC 詳細: `dev-journal/deliverables/docs/10_requirements/rbac.md`

## 1. 認証

| 項目 | 方針 |
|------|------|
| 認証方式 | メールアドレス + パスワード |
| パスワードハッシュ | Argon2id |
| パスワード要件 | 最小8文字 |
| トークン方式 | JWT（アクセストークン + リフレッシュトークン） |
| 署名アルゴリズム | RS256（非対称鍵） |
| アクセストークン有効期間 | 15分 |
| リフレッシュトークン有効期間 | 7日 |
| ログアウト | リフレッシュトークンを無効化（DB or ブラックリスト） |

### 禁止事項
- パスワードの平文保存・ログ出力
- JWT のペイロードに機密情報（パスワードハッシュ等）を含めない
- 認証失敗レスポンスでユーザーの存在を推測させない（「メールアドレスまたはパスワードが正しくありません」で統一）

## 2. 認可（RBAC）

| 項目 | 方針 |
|------|------|
| ロール | Admin / Approver / Member / Accounting の4種 |
| 検証方式 | 全APIエンドポイントでミドルウェアによるロール検証 |
| 所有権チェック | ロール検証に加え、リソース所有者の確認をハンドラ or ドメイン層で実施 |
| 権限不足時 | 403 Forbidden を返却 |
| 他テナントリソース | 404 Not Found を返却（存在漏洩防止） |
| 自己承認 | 禁止（Approver が自分のレポートを承認不可） |

### 禁止事項
- ハンドラ層での直接的なロール文字列比較（ミドルウェアを経由すること）
- 認可チェックのスキップ（テスト用エンドポイントでも例外なし）

## 3. テナント分離

| 項目 | 方針 |
|------|------|
| 分離方式 | 共有DB + tenant_id による論理分離 |
| アプリ層 | リポジトリ層で全クエリに WHERE tenant_id = ? を強制 |
| DB層 | PostgreSQL RLS でテナント分離を二重保証 |
| S3 | オブジェクトキーにテナントIDを含む（`{tenant_id}/{report_id}/{file_id}`） |

### 禁止事項
- tenant_id なしの SELECT / INSERT / UPDATE / DELETE
- ハンドラ層での直接SQL実行（リポジトリ層を経由すること）
- テナント横断クエリ（管理者向けダッシュボード等も対象外）

## 4. レート制限

| 対象 | 制限値 | 単位 |
|------|--------|------|
| 認証済みリクエスト | 100 req/min | ユーザー単位 |
| 未認証リクエスト | 20 req/min | IP単位 |
| ログイン試行 | 5 req/min | IP単位（ブルートフォース対策） |
| ファイルアップロード | 10 req/min | ユーザー単位 |

### 制限超過時
- HTTP 429 Too Many Requests を返却
- `Retry-After` ヘッダーで再試行可能時刻を通知

## 5. ファイルアップロード

| 項目 | 方針 |
|------|------|
| 許可形式 | JPEG, PNG, PDF |
| サイズ上限 | 5MB / ファイル |
| 検証方法 | MIMEタイプ検証（拡張子だけでなくマジックバイトも確認） |
| 保存先 | S3（直接アクセス不可、署名付きURL経由のみ） |
| 署名付きURL有効期間 | 15分 |
| 認可チェック | URL発行前にテナント分離 + ロール + 所有権を検証 |

### 禁止事項
- クライアントから送られたファイル名をそのままS3キーに使用しない
- ファイルの公開バケット設定
- 署名付きURL発行時の認可チェック省略

## 6. 通信・ヘッダー

| 項目 | 方針 |
|------|------|
| HTTPS | 本番環境では必須。HTTP → HTTPS リダイレクト |
| HSTS | `Strict-Transport-Security: max-age=31536000; includeSubDomains` |
| X-Content-Type-Options | `nosniff` |
| X-Frame-Options | `DENY` |
| X-XSS-Protection | `0`（Content-Security-Policy に委ねる） |
| Content-Security-Policy | `default-src 'self'`（フロントエンドで適切に設定） |
| CORS | 許可オリジンを環境変数で明示指定。ワイルドカード禁止 |

## 7. 入力バリデーション

| 項目 | 方針 |
|------|------|
| バリデーション層 | フロントエンド（UX）+ バックエンド（セキュリティ、信頼境界） |
| SQL インジェクション | SQLx のパラメータバインディングを使用。文字列結合によるクエリ構築禁止 |
| XSS | React のデフォルトエスケープに加え、`dangerouslySetInnerHTML` 禁止 |
| パストラバーサル | ファイルパスのユーザー入力をそのまま使用しない |
| 金額 | 正の整数のみ（0以下、小数、文字列を拒否） |
| 文字列長 | 各フィールドに最大長を設定（摘要: 500文字、却下理由: 1000文字 等） |

## 8. 依存関係の管理

| 項目 | 方針 |
|------|------|
| Rust | `cargo audit` をCIに組み込み、既知の脆弱性を検出 |
| Node.js | `npm audit` をCIに組み込み |
| 実行タイミング | PR作成時 + 週次の定期実行 |
| 対応方針 | High / Critical は即座に対応。Medium は次スプリントで対応 |

## 9. ログとエラー処理

| 項目 | 方針 |
|------|------|
| 認証イベント | ログイン成功/失敗、ログアウトをログに記録 |
| 認可エラー | 403 / 404（テナント境界超え）をログに記録 |
| エラーレスポンス | 内部実装の詳細（スタックトレース、SQL文等）をクライアントに返さない |
| 機密情報 | パスワード、トークン、個人情報をログに出力しない |

## 10. チェックリスト（実装時の確認用）

### API エンドポイント追加時
- [ ] 認証ミドルウェアが適用されているか（公開APIを除く）
- [ ] ロール検証ミドルウェアが適用されているか
- [ ] 所有権チェックが実装されているか（該当する場合）
- [ ] リポジトリ層で tenant_id フィルタが適用されているか
- [ ] 入力バリデーションが実装されているか
- [ ] エラーレスポンスが内部情報を漏洩していないか
- [ ] レート制限の対象になっているか

### ファイルアップロード機能
- [ ] MIMEタイプ検証が実装されているか
- [ ] ファイルサイズ制限が適用されているか
- [ ] S3キーにテナントIDが含まれているか
- [ ] 署名付きURL発行前に認可チェックがあるか
