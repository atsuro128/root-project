# テスト方針

## 基本方針
- ビジネスロジック（ドメイン層・リポジトリ層）は単体テスト必須
- ハンドラ層は統合テストで検証
- フロントエンドはコンポーネント単体テスト + E2Eテスト

## Backend (Rust)
- `#[cfg(test)]` モジュールに単体テストを配置
- リポジトリ層のテストはテスト用DBに対して実行（インメモリ不可）
- テストコード内の `unwrap()` は許容

## Frontend (TypeScript)
- Vitest によるコンポーネント・ユーティリティのユニットテスト
- E2Eは Playwright を使用（主要フローのみ）

## カバレッジ目標
- ドメイン層: 80% 以上
- その他: ベストエフォート（過度なモックは避ける）

## テストデータ
- テナント分離を意識し、テスト間でテナントIDが混在しないよう注意
- 機密情報はフィクスチャに含めない
