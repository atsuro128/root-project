セッションの振り返りを実施してください。

## 目的

セッション中に発生した手戻り・指摘・判断ミス・改善点を knowledge エントリとして記録する。
ルール化は別スキル（`/self-review`）が担当する。ここでは事実と学びの記録に徹する。

## 手順

### 1. セッションの振り返り

会話履歴を遡り、以下を洗い出す:

| 種別 | 探すもの |
|------|---------|
| 手戻り | ユーザーに指摘されて修正したこと |
| 判断ミス | 誤った前提で作業を進めたこと |
| 手順漏れ | 本来やるべきだった手順を飛ばしたこと |
| 良い判断 | うまくいった判断・アプローチ（成功も記録する） |

何もなければ「特になし」でよい。無理に捻り出さない。

### 2. 根本原因の分析（問題があった場合）

各問題について「なぜ起きたか」を分析する:

| 観点 | 例 |
|------|-----|
| 確認不足 | 作業後の状態確認を省略した |
| ルール不備 | 手順に必要なステップが定義されていなかった |
| 思い込み | 前回と同じ状態だと仮定して確認を省略した |
| 二重管理 | 同じ情報が複数箇所にあり、片方の更新を忘れた |
| スコープ外判断 | 自分の判断で「不要」と決めてしまった |

**原則**: 注意力不足で片付けない。仕組みで防げる原因を探す。

### 3. knowledge エントリの作成

`/root-project/ai-dev-framework/knowledge/` に以下の形式でファイルを作成する:

**ファイル名**: `YYYY-MM-DD-{slug}.md`（同日に複数ある場合は slug で区別）

```markdown
# {タイトル}

## 日付
YYYY-MM-DD

## 種別
{手戻り | 判断ミス | 手順漏れ | 良い判断}

## 何が起きたか
{事実を簡潔に}

## なぜ起きたか
{根本原因の分析}

## 学び
{次回以降に活かせる教訓}

## 改善のヒント
{ルール追加・手順修正・hook追加などの具体案。/self-review が判断材料として使う}

## ルール化
未対応
```

### 4. 報告

作成したエントリの要約をユーザーに報告する。
