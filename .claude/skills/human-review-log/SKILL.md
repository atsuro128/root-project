レビューセッションの会話内容を分析し、レビューログを作成してください。

## 出力先

- アクティブログ: `dev-journal/review-log.md`（直近2セッション分を保持）
- 確認済み累積: `dev-journal/archives/review-logs/confirmed.md`

## 出力形式

### review-log.md

```markdown
# レビューログ

## レビュー: YYYY-MM-DD HH:MM

### 対象
- レビューした成果物・ファイル

### 確認済み
- 理解が完了した範囲を箇条書き

### 未確認
- まだ確認していない範囲

### 発見した issue
- 起票した issue の番号と概要（なければ「なし」）

### 疑問・メモ
- 理解が曖昧な点、次回確認したいこと

### 学んだこと
- 技術的な学び（言語仕様、設計パターン、セキュリティ等）

---

## レビュー: YYYY-MM-DD HH:MM（前回）

（同じ形式）
```

### confirmed.md

```markdown
# レビュー確認済み一覧

## Step 8: 基盤構築

- [YYYY-MM-DD] 確認した範囲の概要
- [YYYY-MM-DD] 確認した範囲の概要

## Step 9: テストコード実装

- [YYYY-MM-DD] 確認した範囲の概要
```

## 作成手順

1. `date` コマンドで現在時刻を取得する
2. セッションの会話内容を分析する
3. 既存の `review-log.md` を読み込む（なければ新規作成）
4. アーカイブ処理を行う（後述）
5. 確認済み累積を更新する（後述）
6. 新しいレビュー分を先頭に、前回レビュー分を「前回」として残す形で `review-log.md` を書き出す
7. ユーザーに内容を提示し、修正があれば反映する

## アーカイブ処理

`review-log.md` には直近2セッション分のみ保持する。3セッション以上のデータがある場合、古いものをアーカイブに退避する。

1. 既存の `review-log.md` に2セッション分が既にある場合:
   - 「前回」セッション（古い方）のブロックを日付ファイルにアーカイブする
   - 現在の「最新」を「前回」に繰り下げる
   - 新しいレビュー分を「最新」として書く
2. 1セッション分しかない場合:
   - そのセッションを「前回」としてそのまま残す
   - 新しいレビュー分を「最新」として書く

日付ファイルのアーカイブ先: `dev-journal/archives/review-logs/YYYY-MM-DD.md`
- 同日に複数セッションがある場合は同一ファイルに追記する

## 確認済み累積の更新

毎回のレビューセッション終了時に `confirmed.md` を更新する。

1. `dev-journal/archives/review-logs/confirmed.md` を読み込む（なければ新規作成）
2. 今回のセッションの「確認済み」項目を、対応する Step セクションに追記する
   - 形式: `- [YYYY-MM-DD] 確認した範囲の概要`
   - Step セクションがなければ作成する
3. 重複する項目は追加しない

## コミット

review-log の作成後、dev-journal の変更をコミットする。

1. `dev-journal` で `git status` を確認
2. 変更ファイルをステージ
3. Conventional Commits 形式（日本語）でコミット
4. フッター: `Co-Authored-By: Claude <noreply@anthropic.com>`
5. `git push` はしない
