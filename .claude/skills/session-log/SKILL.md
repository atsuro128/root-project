セッションログを記録してください。

## 手順

1. **【必須】`date '+%Y-%m-%d %H:%M'` で現在の日付と時刻を取得する（推測・仮置き厳禁）**
2. `dev-journal/logs/YYYY-MM-DD/session-log.md` が既に存在すれば読み込む（追記のため）
3. 今回のセッションで行った作業・判断を振り返り、下記の形式に従って追記する
4. セッションログを含めてコミットする

## 記載内容

1. **作業要約** — そのセッションで何をやったか（カテゴリタグ付き）
2. **判断事項**（該当がある場合のみ） — 設計方針の決定・運用ルールの変更・スコープの採否・技術選定・方針転換など
3. **問題・ブロッカー**（該当がある場合のみ） — 発生した問題と解決状況
4. **確認事項**（該当がある場合のみ） — ユーザーへの確認待ち、次セッションへの申し送り

## カテゴリタグ

`作業:` 行の先頭に以下のタグを付ける:

| タグ | 用途 |
|------|------|
| `[設計]` | Step 成果物の作成・修正 |
| `[基盤]` | DevContainer・CI/CD・インフラ等の環境構築 |
| `[プロセス]` | スキル・ルール・ワークフローの整備 |
| `[レビュー]` | レビュー実施・指摘対応 |
| `[修正]` | バグ修正・不具合対応 |

## 形式

```markdown
## HH:MM セッション
- 作業: [タグ] 作業内容の要約
- 判断: 判断内容（理由: 背景・根拠）
- 問題: 発生した問題（解決: 解決方法 / 未解決）
- 確認: 確認内容 → 結果
```

- **`HH:MM` は `date` コマンドの出力をそのまま使うこと**（推測・丸め・仮置き厳禁）
- 該当がない行は省略してよい
- 1セッションで複数の作業を行った場合は `作業:` 行を複数記載する

## ファイル

- パス: `dev-journal/logs/YYYY-MM-DD/session-log.md`
- 1日1ファイル（複数セッションは同一ファイルに追記）

## 横断検索

各行は接頭辞で統一されているため、横断検索で一覧できる:
```bash
grep "判断:" dev-journal/logs/*/session-log.md
grep "問題:" dev-journal/logs/*/session-log.md
grep "\[基盤\]" dev-journal/logs/*/session-log.md
```
