セッションの会話内容を分析し、セッションログを作成してください。

## 出力先

`dev-journal/progress-management/session-log.md`（直近1セッション分のみ保持）

## 出力形式

```markdown
# 引き継ぎメモ

## セッション: YYYY-MM-DD HH:MM

### ゴール
- このセッションで合意した作業目標

### 作業ログ
- やったことを時系列で箇条書き
- 判断・決定事項があればその理由も記載

### 未完了
- 着手したが終わっていない作業

### ブロッカー
- 作業を阻害している問題（なければ「なし」）

### 次にやること
- 次セッションで最初にやるべきことを優先順で記載
- 具体的なアクション（「issue 024 のエージェント実行」等）

### 学び・気づき
- 手戻り・判断ミス・手順漏れ・良い判断を簡潔に記録
- なければ「特になし」（無理に捻り出さない）

### 意思決定ログ
- 次セッションで知っておくべき背景情報
- 議論の経緯で重要なもの
```

## 作成手順

1. `date` コマンドで現在時刻を取得する
2. `progress.md` の現在のフェーズを確認する
3. セッションの会話内容を分析する
4. 既存の `session-log.md` を読み込む
5. アーカイブ処理を行う（後述）
6. 新しいセッション分を先頭に、前回セッション分を「前回」として残す形で `session-log.md` を書き出す
7. ユーザーに内容を提示し、修正があれば反映する

## アーカイブ処理

`session-log.md` には直近1セッション分のみ保持する。既存のセッションデータはアーカイブに退避してから新しいセッション分で上書きする。

### 手順

1. **退避対象の有無を確認**
   - 既存の `session-log.md` を Read する
   - 空または存在しない場合は手順 6 にスキップ
2. **アーカイブ先パスを決定**
   - 退避対象セッションの開始日から `dev-journal/archives/session-logs/YYYY-MM-DD.md` を組み立てる
   - ⚠️ **絶対禁止**: `-1`, `-2`, `-session1` 等のサフィックスを付けて別ファイル化してはならない。同日は必ず1ファイルに集約する
3. **アーカイブ先の存在を確認**
   - `Read` でアーカイブ先パスを読む（存在しない場合はエラーが返る）
4. **アーカイブ先が存在しない場合**
   - 退避対象セッションの内容を `Write` でアーカイブ先に新規作成する
   - 形式: 先頭に `# 引き継ぎメモ` を1行、続けて `## セッション: YYYY-MM-DD HH:MM` 配下のセッション本文
5. **アーカイブ先が既に存在する場合（同日に既存セッションあり）**
   - `Edit` ツールで既存ファイルの末尾に追記する
     - `old_string`: 既存ファイル末尾の数行（一意になるように）
     - `new_string`: 既存末尾 + `\n\n---\n\n## セッション: YYYY-MM-DD HH:MM` 以降の退避内容
   - 既存ファイル内のセッションと開始時刻順になるよう挿入位置を判断する（通常は末尾追記でよい）
   - ⚠️ `Write` で上書きしないこと。既存セッションを失う
6. **新しいセッション分で `session-log.md` を上書き**
   - `Write` で新セッション分を書き出す

## クリーンアップ

引き継ぎメモ作成後、以下を実施する:

1. `.claude/worktrees/` にディレクトリが残っていれば削除する
2. `git worktree list` で不要なワークツリーが登録されていれば `git worktree remove` で除去する

## コミット

クリーンアップ完了後、全リポジトリの未コミット変更をコミットする。

1. 各リポジトリ（root-project, dev-journal, ai-dev-framework, expense-saas）で `git status` を確認
2. 変更があるリポジトリごとに、そのディレクトリで以下を実行:
   - 変更ファイルをステージ
   - Conventional Commits 形式（日本語）でコミット
   - フッター: `Co-Authored-By: Claude <noreply@anthropic.com>`
3. 各リポジトリで `git push` する（リモートへのバックアップ）
   - expense-saas は PR ベースで運用するため、master への直接 push はスキップ
