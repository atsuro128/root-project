成果物のウォークスルー（設計説明会）を実施してください。

対象: 

## コンセプト

人間チームの設計説明会を再現する。
- **IDE が画面共有**: ユーザーにファイルを開いてもらう
- **テキスト出力が口頭説明**: セクションごとに設計意図・判断理由を解説する
- **ユーザーは聞き手**: 質問・指摘があればその場で対応する

## 実行手順

### 1. 対象ファイルの特定

引数でファイルパスが指定されている場合はそのファイルを使用する。
指定がない場合は、直近で作成・修正された成果物を提案する。

### 2. ファイルを読む

対象ファイルを Read で全文読み込む。
関連する上流文書（画面仕様、共通コンポーネント設計等）も把握しておく。

### 3. IDE で開くよう依頼

「IDE で以下のファイルを開いてください」とユーザーに伝え、準備ができたら教えてもらう。

### 4. セクションごとの解説

ファイルの各セクションについて、以下の形式で解説する:

```
### §N セクション名（行番号）

[設計内容の要約 — 何がどうなっているか]

[設計意図・判断理由 — なぜそうしたか]

[上流文書との対応 — どの仕様に基づいているか]

質問や違和感はありますか？
```

#### 解説のルール

- 1回の発言で扱うのは **1〜2セクションまで**（情報量の制御）
- ファイルの内容をそのまま読み上げない — **要約 + 設計意図** を説明する
- 上流文書との関係（「画面仕様の §N に基づいて〜」）を必ず触れる
- 専門用語はユーザーの知識レベルに合わせて補足する
- 各セクション後に **必ず質問タイムを設ける**（「質問や違和感はありますか？」）

### 5. 指摘への対応

ユーザーから指摘があった場合:
- 軽微な修正: その場で Edit して続行
- 設計判断の変更: issue として起票するか、その場で方針を決める
- 別ファイルへの波及: 影響範囲をメモし、ウォークスルー後にまとめて対応

### 6. 完了

全セクション完了後、以下を確認:
- 指摘事項のまとめ（あれば）
- 未対応の修正があれば対応方針の確認
- 次の画面/ファイルに進むか確認

## 注意事項

- ユーザーの「次」「オーケー」は「このセクションは問題なし、次へ」の意味
- 長い沈黙や短い返答は理解の確認ではなく、先に進んでほしいサイン
- 説明が長すぎると聞き手が疲れる — 簡潔に、ポイントを絞る
- ウォークスルー中に発見した問題は、フローを止めずにメモして後で対応
