ミス発生時のふりかえりを実施してください。

## 1. 根本原因の特定

以下の観点で「なぜ起きたか」を掘り下げる:

| 観点 | 例 |
|------|-----|
| 作業ディレクトリの誤り | 相対パスで想定と違うディレクトリに作用した |
| 確認不足 | git add 後にステージ内容を確認しなかった |
| ルールの不備 | 手順に検証ステップが含まれていなかった |
| 思い込み | 前回と同じ状態だと仮定して確認を省略した |

## 2. 防止策の決定

以下のいずれかに分類し、対策を実施する:

| 分類 | 対策 | 例 |
|------|------|----|
| 手順の追加 | 既存ルールに検証ステップを追記 | commit スキルに「コミット後に git show で内容確認」を追加 |
| hook の追加 | 自動検証で再発を防止 | stop-check に新しい検証を追加 |

**原則**: 人間の注意力に頼る対策は避け、仕組み（ルール明文化・hook）で防ぐ。

## 3. Issue 起票

根本原因と防止策をまとめた上で、`/issue 起票` を実行する。

- **カテゴリ**: `ai-ops`
- **発見経緯**: `user-report`（ユーザー指摘の場合）または `proactive`（自分で気づいた場合）
- **問題**: 根本原因の分析結果を記載
- **提案**: 防止策（手順追加・hook 追加など具体的な対策）を記載
