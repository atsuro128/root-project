ミス発生時のふりかえりを実施してください。

## 1. 根本原因の特定

以下の観点で「なぜ起きたか」を掘り下げる:

| 観点 | 例 |
|------|-----|
| 作業ディレクトリの誤り | 相対パスで想定と違うディレクトリに作用した |
| 確認不足 | git add 後にステージ内容を確認しなかった |
| ルールの不備 | 手順に検証ステップが含まれていなかった |
| 思い込み | 前回と同じ状態だと仮定して確認を省略した |

## 2. 防止策の決定

以下のいずれかに分類し、対策を実施する:

| 分類 | 対策 | 例 |
|------|------|----|
| 手順の追加 | 既存ルールに検証ステップを追記 | commit スキルに「コミット後に git show で内容確認」を追加 |
| memory への記録 | `.claude/memory/lessons-learned.md` に教訓を追記 | 「マルチリポジトリ構成では pwd を確認してからファイル操作する」 |
| hook の追加 | 自動検証で再発を防止 | stop-check に新しい検証を追加 |

**原則**: 人間の注意力に頼る対策は避け、仕組み（ルール明文化・hook）で防ぐ。

## 3. 記録

`.claude/memory/lessons-learned.md` に以下の形式で記録する:

```markdown
### YYYY-MM-DD: [ミスの要約]
- 原因: [根本原因]
- 対策: [実施した防止策]
- 対策先: [修正したファイルパス]
```

## 4. ルール・手順の更新

対策として既存ルールの修正が必要な場合は、該当ファイルを直接修正する。
修正後、ユーザーに変更内容を報告する。

## 注意事項
- 対策の粒度は最小限にする（過剰なチェックリスト化は逆効果）
- 同種のミスが3回以上記録された場合は、hook による自動化を検討する
