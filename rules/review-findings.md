# レビュー指摘対応ルール

## 対象

レビュー（初回・再レビュー）で発見された指摘事項への対応を管理する。
issue（作業中に発見した設計上の問題）とは別管理。

## フォルダ構成

```
review-findings/
├── open/             # 未対応の指摘
├── pending-review/   # 対応済み・レビュー待ち
└── resolved/         # 再レビュー完了・クローズ済み
```

## Claude Code の責務

1. **指摘内容の確認**: `review-findings/open/` の指摘ファイルを読み、対応すべき内容を把握する
2. **成果物の修正**: 指摘に基づき `deliverables/` 等の成果物を修正する
3. **review-findings/ のファイルは編集しない**: 指摘ファイルの作成・移動・編集はレビュアー側の責務

## ライフサイクル（Claude Code 視点）

1. ユーザーから指摘対応の指示を受ける
2. `review-findings/open/` の該当ファイルを読む
3. 成果物を修正する
4. 修正内容をユーザーに報告する（指摘ファイルの移動はレビュアーが行う）

## issue への昇格

指摘のうち、独立した設計判断が必要で対応が大きいものは issue に昇格させる（`rules/issue-management.md` 参照）。
昇格の判断はユーザーに確認すること。
